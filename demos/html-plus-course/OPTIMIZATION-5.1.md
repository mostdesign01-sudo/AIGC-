## 3. 系统优化建议（P0 → P2）

格式：编号 · 类型 · 目标 · 为什么 · 改什么（精确到选择器 / 行）。

### P0

**P0-1 · 交互 · 全局「点字可改」改为显式编辑模式**
为什么：现在点卡片文字不触发动作，这是所有互动页（P02/04/07/09/10/11/13/14/18）的共同故障，手机端尤甚。
改什么：`bindEdits()`（L2055–2073）改为默认 `contenteditable="false"`；新增 `body.is-edit` 开关，入口 = dock 的「点字可改」文字改为按钮「改字」+ 键盘 `E`；仅在 `is-edit` 下设 `contenteditable=true` 并显示虚线框；退出编辑时全部关掉。容器里的 `closest("[contenteditable]")` 守卫保留（编辑态下才会命中）。`editSel` 里剔除冻结元素（见 P1-4）。

**P0-2 · 布局 · P01 封面去掉照片，或 Klein 遮罩 ≥ 0.78**
为什么：白字压砖墙不可读；门前已经承担了「楼」的功能，P01 是课的第一页，应该干净。
改什么：删 `.cover > .door-field`（L1377–1379）和相关 `.cover.is-push .door-still` 规则；`.cover.klein-field` 保持纯 Klein。若 Hao 坚持要照片，`.door-field::after` 改为 `linear-gradient(90deg, rgba(0,47,167,.92) 0%, rgba(0,47,167,.78) 55%, rgba(0,47,167,.55) 100%)`，且照片只允许出现在标题右侧 40% 区域。

**P0-3 · 布局 · 门前照片规则：没有 T7 原图就回到纯 Klein**
为什么：当前是互联宝地二期，不是得物大楼，PR #6 自己也承认「错楼已撤、T7 待补」。错楼比没楼更糟。
改什么：`#loader` 在 `door-still.webp` 不是 T7 之前，`.door-field img` 不渲染（或直接删除 webp 引用），保留 `.cine-word` HTML+ 大字 + 左下文案，恢复到附图 1 的纯蓝门前层级；文案块 `.loader-copy` 无论有无照片，底部加 `rgba(0,47,167,.6)` 到透明的 40vh 渐变垫底。`t7-3.jpg` 落盘后再启用照片，且 `object-position` 让三拱门在下 1/3。

**P0-4 · 文案 · P06 四步与 P07 四个动作统一**
为什么：相邻两页出现两套不同的「四个词」，学员记不住任何一套。
改什么：P06 `.flow`（L1462–1467）四步标题改为 `装下内容 / 组织信息 / 接收操作 / 给出回应`，小字保留活动通知语境（如「通知、流程、注意在一页」「先选身份再看流程」「点一下，页知道你是谁」「拿到自己的下一步」）。P07 不变。

**P0-5 · 交互 + 文案 · P07 金句必须在「内容变了」的那一刻放大出现**
为什么：金句是全课的核心，现在是 13px 的底栏。
改什么：`.demo` 内 `.klein-bar`（L1495）在未选身份时隐藏；选身份后 `#next-step` 更新的同时，金句以 `clamp(18px, 2vw, 22px)` 在 `.demo` 下半部淡入（`.demo` 现在 60% 是空的，正好放）。同时四个动作卡与演示对应：点 01 高亮通知正文块；点 02 高亮「请选择你的身份」+ 身份按钮组；点 03 让身份按钮脉冲一下；点 04 高亮 `#next-step`。选完身份后 01–04 顺序全亮，而不是只亮 03/04。

**P0-6 · 布局 · P04 定义做成主视觉**
为什么：定义是唯一「一字不改」的解释句，现在最小。
改什么：`.quote`（L1409）字号提到 `clamp(20px, 2.2vw, 28px)`，左侧 2px 极光青竖线加粗到 3px，占页面上 45%；pills 缩成一行小字放定义下方；`.vs` 旧/新认知与 `#jobs` 六张岗位卡合并成一块（岗位卡即「新认知」的证据），`.jobs` 改为 3×2 更矮的按钮。手机端顺序：定义 → 新认知 → 岗位卡。

**P0-7 · Bug · P13 T恤工具可见**
为什么：字标 / 贴花 / 吊牌按钮与「拖一拖 · 换贴花」提示被 `height:118%` 推出可视区，案例一的「接收操作」在台上看不到。
改什么：`.device-view > .tee` 去掉 `height:118%` 与 `translateX` 规则（L711–722），改为 `position:absolute; inset:0;`；`.tee-tools` / `.tee-cap` 的 `bottom` 改为 `calc(klein-bar 高 + 8px)`，或把工具移到 `.device-chrome` 右侧。`.klein-bar` 见 P1-1。

### P1

**P1-1 · 布局 · `.klein-bar` 不截断**
改什么：L395 `white-space: nowrap; text-overflow: ellipsis` 删除，允许两行；`.device-view` 底部 `padding-bottom` 预留两行高度。文案同时压短到 ≤ 28 字（见 P1-6）。

**P1-5 · 布局 · P05 与 P11 去重**
改什么：P05 保持「四种打开方式」对照，但四列改为上下两行（上：形式 + 一句适用；下：`.more`），卡高随内容；P11 左栏 `.rows` 改成「先排除，再留下」的阶梯（前三行灰、第四行 Klein 保持），每行加一句「什么时候就够了」；右栏 `.check` 改 `text-align:left`，与左栏对齐；`.is-stop` 保持现在的常亮，不参与单选。

## 4. 执行批次（Grok 4.6）

每批一个主题、一个 commit、一次 PR 更新；做完跑第 6 节对应项；不跨批带工作。

### 批次 A · 能点能读（P0-1、P0-2、P0-3、P0-7、P1-1、P2-5）
范围：只改 CSS/JS 结构和门前 / 封面层，不碰任何文案。
成功标准：
- 桌面 + 手机点任意卡片上的文字都触发动作；只有按「改字」/`E` 后才进入编辑，退出后虚线框全消失。
- 门前无照片时是纯 Klein，`HTML+` 大字 + 文案 + 按钮层级与附图 1 一致；有照片时文案区对比度 ≥ 4.5:1。
- P01 副标题、开场问题在 390 宽下可读（无照片或遮罩 ≥ .78）。
- P13 可见字标 / 贴花 / 吊牌三键与「拖一拖 · 换贴花」；拖动仍可转 ±40°。
- P13 / P14 `.klein-bar` 完整显示，无省略号。

### 批次 B · 主线文案与重点句（P0-4、P0-5、P0-6、P1-4、P1-5、P1-6）
范围：P04 / P05 / P06 / P07 / P11 文案与层级；冻结句加 `data-frozen`。
成功标准：
